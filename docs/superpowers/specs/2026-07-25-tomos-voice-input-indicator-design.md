# TOMOS音声入力インジケーター設計

## 目的

会話欄で、マイクが音を受け取っているか、TOMOSが声として判定したか、
文字起こしを確定しているかをユーザーが区別できるようにする。

## 対象範囲

- 会話欄の音声入力中に表示する5段階メーター。
- 入力状態に合わせた短い日本語表示。
- VADへ渡すRMS・peak値から表示レベルを求める純粋関数。
- PC、Tauriアプリ、スマートフォン幅で同じ状態契約を使う。

設定画面の診断用パーセント表示、VAD閾値、ASRモデル選択、音声保存方法は変更しない。

## 表示仕様

既存の音声状態表示内に、入力に連動する5本の縦バーを置く。
通常画面では数値パーセントを表示しない。

| 状態 | メーター | 表示文 |
| --- | --- | --- |
| マイク開始前 | 非表示 | なし |
| 入力待機・無音 | 0 | 音声を待っています |
| 小さな入力あり | 1 | 音を受け取っています |
| VAD候補 | 2 | 声を認識しています |
| 発話中 | 3 | 声を認識しています |
| 強い発話 | 4 | 声を認識しています |
| 確定処理中 | 最後の値を静止 | 音声を確定しています |
| 停止・失敗 | 非表示 | 既存の停止・エラー文 |

色だけに依存せず、バーの本数と状態文を同時に変える。
メーターは装飾要素として読み上げ対象外にし、状態文は既存の
`composer-status`から支援技術へ伝える。

## 状態とデータの流れ

1. `createWavPartialCapture()` が各音声chunkのRMS・peakを算出する。
2. 純粋関数がRMS・peak・VAD phaseから0から4の表示レベルを返す。
3. `onAudioLevel` callbackで会話欄だけを更新する。
4. VADの`candidate`または`speaking`では「声を認識しています」を表示する。
5. 自動確定、ユーザー停止、エラー、session終了時に更新を停止して表示を片付ける。

表示更新は最大10回/秒に制限する。音声chunk、RMS、peak、最大値を
Memory、Knowledge、localStorage、ログ、ファイルへ保存しない。

## 判定境界

- レベル0: 無音相当。
- レベル1: 音声信号はあるがVAD閾値未満。
- レベル2: VADの`candidate`。
- レベル3: VADの`speaking`。
- レベル4: `speaking`中の強い入力。

レベル2以上は既存VADのRMS 0.003またはpeak 0.01を正とする。
表示用のレベル1と4は文字起こし開始条件を変更しない。

## エラー処理

- AudioContextが使えない場合はメーターを非表示にし、既存エラーを表示する。
- session IDが一致しない更新は破棄する。
- 停止後の遅延callbackは表示へ反映しない。
- 表示処理の失敗で録音・停止処理を中断しない。

## テスト

- RMS・peak・VAD phaseから0から4へ変換するpure helper test。
- 無音、小さな入力、candidate、speaking、強い入力の境界test。
- stop後、session不一致、finalize後に更新しないtest。
- PC幅1440×900、Tauriアプリ1280×820、スマートフォン幅390×844の表示確認。
- アプリ実声テストで、発話中にバーと状態文が変わることを確認する。

## 完了条件

- ユーザーが「マイク入力なし」「音は届いている」「声として判定済み」を区別できる。
- 既存VAD、停止、stale response破棄、ASR fallbackのtestが回帰しない。
- 音声および入力レベルの永続保存が0件。
